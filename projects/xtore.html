Overview

The seller side of Xtore

The Xtore mobile app gives merchants quick access to day-to-day store operations — inventory, orders, and live selling — while a separate web dashboard handles more advanced management and configuration. My work focused on the merchant-facing mobile workflows: shipping, Box Break, and Live Events.

I worked independently on these areas as one of two UI/UX interns on Xtore; the other intern was responsible for Wallet and Order Transactions.

My Role

Contribution

User flow exploration Wireframing UI design Interaction design Error & fallback states State management Prototyping Design documentation Developer collaboration Iteration

I worked directly with my supervisor through the initial design stages. After revisions, the development team reviewed the designs before further refinement and approval — and some work was shared with the CEO for feedback early in development.

Challenge

Designing for the workflow, not just the screen

Designing merchant tools meant thinking beyond the ideal user journey. Each feature had to account for different states, actions, fallbacks, and possible outcomes — while staying simple enough for merchants to use during actual day-to-day operations, not just in a demo.

Process

From rough flow to implementation

Rough flow→Wireframes→Exploration→High-fidelity UI→Review→Refinement→Implementation

Planning started with rough FigJam sketches focused on placement and sequencing — thinking through the end-to-end process before any visual design began. For every feature, I mapped what the merchant would need to do from the start of the task through to completion, before deciding how any single screen should look.

Shipping Management

Refining how merchants organize shipping categories

Merchants needed a way to create and manage reusable shipping categories while keeping package dimensions, weight, fulfillment methods, and category status easy to review. The design exploration focused on improving how these details were presented and how merchants navigated their shipping configurations.

Approach A

Grouped categories by status; fulfillment details were less prominent.

Approach B

Improved detail visibility and scanability with clearer status indicators and filters.

Final direction

Grouped categories by fulfillment method; easier to browse courier delivery and pick-up options.

Beyond the happy path

Every shipping screen also needed an edit state, a delete confirmation, a success state, an empty state for a merchant with no shipping set up yet, and a fallback for when a shipping update failed to save.

Box Break

Designing a listing with six possible states

Box Break listings move through a lifecycle with real consequences at each stage — a listing that's "Live" behaves and displays very differently from one that's merely "Upcoming," and a cancelled listing needed to be unmistakably different from both.

Draft→Upcoming→Slots available→Live→Live ended

Live Event

Designing for the seller during a live session

Live Event covers setup, the live interface itself, monitoring, and seller controls — all while the session is actively running, which meant the design had to prioritize glanceable status over dense information.

Key Design Decision

Designing beyond the happy path

One of my biggest learnings from Xtore was that designing a feature doesn't stop at the main successful flow. I had to account for editing, deleting, errors, fallbacks, empty states, and every stage a listing could actually be in.

Reflection

What I learned

01

Think through the complete user journey, not just the ideal path.

02

Design for edge cases and fallbacks as a first-class part of the work.

03

Consider every state a screen can be in before finalizing its UI.

04

Make complex operational workflows feel simple to use daily.

05

Collaborate closely with developers who have to build each state.

06

Treat revisions as part of the design process, not a detour from it.
